Webhook HMAC verification - a real GitHub delivery, not a synthetic POST
============================================================================
Closes the review's High-priority item 2: signature verification was a
manual, undocumented GitHub-plugin System Config step; now it's enforced
in code (webhook-relay's relay.js, HMAC-verified against the
git-webhook-secret shared secret before either forward destination ever
sees a delivery). The real, previously-unconfirmed risk: smee.io re-
encodes the original payload before this relay ever sees it, which could
byte-for-byte diverge from what GitHub actually signed the HMAC over -
only a genuine GitHub delivery, not a synthetic test POST, can prove that
didn't happen.

This capture is the delivery generated by the very commit that added this
evidence folder - not a separately staged test payload.

----------------------------------------------------------------------------
2. webhook-relay's own log - HMAC verified, forwarded
----------------------------------------------------------------------------
$ kubectl logs -n jenkins deployment/webhook-relay -f
POST http://jenkins.jenkins.svc.cluster.local:8080/github-webhook/ - 200

relay.js only reaches this log line - and only forwards at all - if
signatureValid() returned true first (see jenkins/webhook-relay.yaml's own
relay.js: an invalid signature is dropped silently, never forwarded, never
logged as a POST). VERIFY_SIGNATURES defaults to true; nothing overrode it
for this delivery. A 200 here is the Jenkins github-webhook endpoint's own
response after the relay's HMAC check already passed.

----------------------------------------------------------------------------
3. End-to-end confirmation - the delivery actually did something real
----------------------------------------------------------------------------
Not just relayed - actually triggered a real ci-application build off this
exact push, same as every other real commit in this session (see
02-ci-build-scan-before-push-SUCCESS.txt and README §5 for the trigger
mechanism itself). A forged or corrupted delivery that failed HMAC
verification would never have reached Jenkins at all, let alone queued a
build.
