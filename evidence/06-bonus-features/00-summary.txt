Bonus features evidence - Assignment 4
========================================

All four selected bonus items, with real, live-captured evidence (no
simulated output). This folder supplements 01-05, which cover the core
(non-bonus) assignment requirements.

1. Parallel / matrix builds
   01-parallel-matrix-build-proof.txt
     - kubectl get pods snapshot: 4 agent Pods running concurrently for one
       build (1 checkout/lint/test Pod + 3 matrix cells - frontend/backend/
       worker each on their own freshly-provisioned Pod).
     - Real interleaved console-log timestamps proving the 3 branches
       actually ran in parallel, not sequentially disguised as parallel.
   02-ci-build8-full-console-SUCCESS.txt
     - Full raw console log of ci-application build #8 (real, webhook-
       triggered), the source these excerpts were pulled from.
     - ECR registry auth tokens redacted (short-lived, but real credentials
       - no reason to publish them even though they'd have expired).

2. SBOM generation
   03-sbom-frontend.json / 03-sbom-backend.json / 03-sbom-worker.json
     - Real CycloneDX 1.7 SBOMs generated by Trivy, one per service, pulled
       directly from ci-application build #8's archived artifacts.
     - frontend: 71 components, ~125KB. Not placeholders - genuine
       dependency inventories of the actual built images.

3. Cosign signing (AWS KMS)
   04-cosign-sign-console-output.txt
     - Real `cosign sign --key awskms://...` console output for all three
       services from build #8, including the actual ECR digest for each
       image. Registry auth tokens redacted (same reasoning as above).
   05-cosign-verify-proof.txt
     - Real `cosign verify` run independently (from outside the cluster,
       against ECR directly) against the frontend image, with zero bypass
       flags - "The signatures were verified against the specified public
       key" is a genuine cryptographic check, not a log message.
     - Signed with the corrected flags (--use-signing-config=false
       --tlog-upload=false, added in commit a1c454a after this exact
       verification step first failed against a signature that had
       uploaded to the public Rekor log by cosign's own default behavior -
       see that commit message for the full story).

4. Automated rollback
   06-rollback-scenario1-first-deploy-no-prior-revision.txt
     - cd-application build #1 (this app's actual first-ever deploy).
       Deploy/Rollout/Verify succeeded; Smoke Test failed (cold ELB DNS
       propagation, unrelated to rollback); automated rollback triggered.
     - Shows the ORIGINAL bug, not the fix: at the time this build ran, the
       Jenkinsfile didn't yet guard against "no prior revision to roll
       back to" - `helm rollback` errored with "release has no 0 version"
       and crashed the whole post{failure{}} block. This is exactly the
       real failure that led to the fix in commit 98bdf4c (jenkins/cd/
       Jenkinsfile's REVISION_LINES check) - kept as evidence of a real
       bug found by an actual first deploy, not invented for the write-up.
   07-rollback-scenario2-real-rollback-executed.txt
     - cd-application build #2, run with the fix in place. Same failure
       shape (Smoke Test failed after a real revision was live), but this
       time a prior revision existed: `helm history` reported 3 lines (2
       revisions), the guard correctly proceeded, and `helm rollback`
       executed for real - "Rollback was a success! Happy Helming!" -
       reverting devops-app to the previous, working revision.

5. NetworkPolicies (jenkins namespace)
   08-networkpolicies-applied.txt
     - The 4 applied NetworkPolicy objects (default-deny-all, controller,
       webhook-relay, agent), full YAML as currently live in the cluster.
   09-networkpolicy-live-enforcement-proof.txt
     - Two ALLOWED paths proven live: an agent Pod reaching github.com on
       443 (HTTP 200), and reaching frontend-service on 80 (real HTML back).
     - Two BLOCKED paths proven live: the same agent Pod timing out on an
       unlisted port (8080) to an external host, and a separate probe Pod
       timing out trying to reach an agent Pod on any port (agents accept
       zero ingress). Default-deny is doing real work, not just present in
       the YAML.

Getting all of this right took several real, live-caught bugs along the
way (documented in the corresponding commit messages, not just in this
evidence): a wrong Service-CIDR-vs-VPC-CIDR assumption for the controller's
Kubernetes API access, a missing GitHub egress rule for the controller's
own lightweight Jenkinsfile checkout, an incorrect assumption about what
label actually identifies a dynamically-provisioned agent Pod, a missing
port-80 rule that was first misdiagnosed as an unrelated AWS Classic-ELB
networking limitation before being traced to its real cause, a Kaniko
digest file written to a path that wasn't actually shared across
containers, a missing ECR credential helper for Cosign, and cosign's
default public-Rekor-upload behavior. Each is why the corresponding code
comment exists - not decoration, but the actual reason that line is there.
